## ما نُفّذ في الكود

Firebase Authentication للهاتف والإدارة، Firestore للطلبات والضيوف، قواعد تمنع الكتابة المباشرة للبيانات الحساسة، Cloud Functions للتحقق وتغيير الحالات، ملفات خاصة في Storage، روابط دعوات عشوائية، وتسجيل رد ودخول ذري على الخادم. لا توجد كلمة مرور إدارة أو OTP ثابتة في الواجهة. السعر يأتي من تعريف الباقات الخادمي.

صفحة `preview.html` مجرد معاينة تصميم معلّمة بوضوح؛ الدعوة الفعلية تستخدم رابطًا شخصيًا في `invitation.html#token=...`.

## ما لم يُفعّل

- ملف `js/firebase-config.js` يحتوي مشروع `medadaltahaya` فقط؛ لا تتوفر إعدادات تطبيق الويب. يبقى `enabled:false` إلى حين اكتمال الإعداد.
- لم تُنشر الدوال والقواعد والفهارس إلى الحساب الحقيقي.
- الدفع الإلكتروني والإرسال الآلي عبر واتساب والتذكيرات الآلية غير منفذة لعدم تحديد المزودين. لا يُنشأ دفع ناجح وهمي ولا مهمة إرسال وهمية.
- إصدار روابط الدعوات يتطلب حالة دفع موثقة وتصميمًا معتمدًا. لا توجد واجهة تسمح للمستخدم باعتبار نفسه دافعًا.
- اختيار التذكير يُحفظ كطلب فقط. لا يُوصف بأنه رسالة مجدولة.

## التشغيل والفحص

تحتاج Node.js 22 لتطابق بيئة الدوال، وJava 21 أو أحدث لاختبار Firebase Emulator Suite.

```bash
npm ci
npm test
npm run serve
```

افتح `http://127.0.0.1:4173`. الصفحات المحمية تعرض حالة الإعداد ما لم تضبط Firebase.

```bash
npm run test:integration
```

هذا الأمر يستخدم المشروع المحلي الوهمي `demo-medad-audit` ويختبر عزل Firestore وStorage ومعاملات الرد والدخول. لا يُوصل الاختبار بقاعدة إنتاج.

نجحت اختبارات المنطق وDOM المحلية. تعذر تشغيل اختبارات Firebase Emulator في بيئة الإصلاح لأن Java المتاح إصدار 17 بينما الأداة تتطلب 21؛ يجب اجتيازها قبل النشر. أُضيف سير اختبار في GitHub Actions يهيئ Java 21، ولم يُشغّل على GitHub بعد.

فحص اعتماديات الإنتاج بـ `npm audit --omit=dev` لا يعرض تنبيهات مسجلة. الفحص الكامل يعرض خمسة تنبيهات متوسطة في اعتماديات تطوير غير مباشرة داخل Firebase CLI؛ لا تدخل في حزمة الواجهة أو دوال الإنتاج، ويجب مراجعتها عند صدور تحديث آمن للأداة.

تم تضمين `js/vendor/firebase.js` المبني محليًا، لذلك لا تحتاج صفحات GitHub Pages إلى تحميل SDK من CDN. أعد `npm run build` عند تغيير الحزم أو التحقق المشترك.
