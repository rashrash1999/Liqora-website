# medad Al tahaya — منصة الدعوات الإلكترونية

نسخة إطلاق مرشحة لمنصة **مداد التحايا**: باقات وتسعير، حساب عميل بالبريد الإلكتروني
الموثّق، طلب مناسبة، دفع مستضاف عبر Moyasar، تصميم واعتماد، قائمة ضيوف خاصة، RSVP،
WhatsApp وتذكيرات مجدولة، تقارير، وبوابة استقبال.

بعد تسجيل دخول العميل بنجاح يعود إلى الصفحة المطلوبة إن كانت محمية، أو إلى الصفحة الرئيسية
عند الدخول المباشر. تعرض لوحة التحكم الطلبات الحالية والسابقة وتتيح تحديث الاسم. البريد
الإلكتروني هو معرّف الدخول، أما رقم الجوال فهو رقم تواصل مستقل محفوظ داخل كل طلب وقابل للتعديل.

> التسجيل العام للضيف متوقف مؤقتًا في الواجهة إلى أن يُختار مزود تحقق مناسب. روابط الضيوف
> الشخصية والقائمة الخاصة تبقيان المسار المعتمد حاليًا. حماية Firebase App Check عبر
> reCAPTCHA Enterprise تبقى فعالة في الخلفية ولا تعني وجود CAPTCHA مرئي في نموذج الدخول.

## ما يعمل في الكود

- ثلاث باقات: البطاقة الذكية، موقع المناسبة المميز، ومداد أعمال.
- إنشاء حساب عميل بالبريد وكلمة المرور، ورسالة توثيق، واستعادة كلمة المرور.
- تسعير تلقائي للباقتين الفرديتين بحسب عدد أرقام الدعوات والإضافات، وعرض سعر إداري لباقة الأعمال.
- فصل **عدد أرقام الدعوات** عن **سعة الحضور** التي تشمل المرافقين.
- قائمة خاصة عبر CSV مع تصنيف عام/رجالي/نسائي وروابط شخصية موقعة.
- عرض تصميم جاهز أو صورة تصميم مخصص خاصة، ثم اعتماد النسخة من العميل قبل النشر.
- دفع Moyasar مستضاف؛ بيانات البطاقة لا تمر بالموقع أو Firestore، ولا تصبح الحالة `paid` من رابط العودة.
- إرسال دعوات وتذكيرات بقوالب WhatsApp Cloud API المعتمدة، مع سجل تسليم ومنع التكرار.
- QR منفصل عن رابط الدعوة، وتسجيل دخول ذري لا يضاعف العدادات.
- تقارير كاملة مرقمة حتى الحد التشغيلي 10,000 ضيف، تشمل الجوال والرد والمرافقين والدخول وعدم الحضور والرسائل.

## رحلة العميل والضيف المعتمدة الآن

1. ينشئ العميل حسابًا بالبريد وكلمة المرور، ويفتح رسالة التوثيق، ثم يسجّل الدخول.
2. يختار الباقة وعدد الدعوات والسعة، ويستخدم وضع القائمة الخاصة وروابط الضيوف الشخصية.
3. يضيف بيانات المناسبة ورقم التواصل والتصميم والتذكيرات. يعيد الخادم التحقق من كل حقل ويحسب السعر.
4. للباقات الفردية يصبح السعر المعتمد متاحًا مباشرة؛ باقة الأعمال تنتظر عرض الإدارة.
5. ينشئ الخادم فاتورة Moyasar مستضافة ويتحقق من نتيجتها خادميًا.
6. للقالب الجاهز توجد نسخة قابلة للاعتماد، وللتصميم المخصص يرفع الفريق الصورة النهائية ويعتمدها العميل.
7. تستورد الإدارة قائمة الضيوف وتصدر رابطًا شخصيًا لكل ضيف.
8. يسجل الضيف رده ومرافقيه ورسالة اختيارية من رابطه الشخصي.
9. تظهر الإحصاءات للعميل والإدارة، وتُرسل التذكيرات المختارة، ثم تمسح بوابة الاستقبال بطاقة QR مرة واحدة.

## ما يحتاج إعداد المالك قبل التشغيل الحقيقي

الكود لا يحتوي أسرارًا، ولا يمكنه إرسال WhatsApp أو تحصيل دفعة بمجرد فك ZIP. يلزم:

1. خطة Firebase تدعم Functions وCloud Scheduler، مع App Check ونطاقات مصرح بها.
2. تفعيل Email/Password في Firebase Authentication للعملاء والموظفين.
3. أسرار Moyasar وWhatsApp في Firebase Secret Manager، ومعرّف رقم WhatsApp وقالبان عربيان معتمدان.
4. نشر قواعد Firestore وStorage والفهارس والدوال المجدولة.
5. بناء `dist` ونشره على Cloudflare Pages.
6. نجاح اختبارات Firebase Emulator ثم تجربة كاملة في Sandbox قبل مفاتيح الإنتاج.
7. مراجعة قانونية لسياسة الخصوصية والشروط وسياسة الإلغاء والاسترداد.

إذا كانت هناك حسابات عملاء حقيقية أُنشئت سابقًا برقم الجوال، فيجب إعداد خطة ربط أو ترحيل
لهوياتهم وطلباتهم قبل نشر هذا التغيير على الإنتاج؛ إنشاء حساب بريد جديد يولّد UID مختلفًا.

## فصل الدفع

- واجهة الدفع: `checkout.html` و`js/checkout.js`.
- نموذج العرض الآمن: `js/payment/checkout-model.js`.
- تحقق السعر: `functions/payment/domain.js`.
- عميل Moyasar السري: `functions/payment/moyasar.js`.
- المعاملات وربط الفواتير: `functions/service.js`.
- Callable Functions وCallback: `functions/index.js`.

المبالغ أعداد صحيحة بالهللات ومن الخادم. معرف العملية يمنع إنشاء فاتورتين عند إعادة المحاولة،
وتُطابق الفاتورة الرسمية مع الطلب والمبلغ والعملة قبل قبول الدفع.

## التشغيل المحلي

المتطلبات: Node.js 22 وJava 21 أو أحدث لاختبارات Firebase Emulator Suite.

```sh
npm ci
npm test
npm run test:integration
```

ثم افتح `http://127.0.0.1:4173`. استخدم مشروعًا تجريبيًا وحسابات اختبار فقط.

## البناء والنشر

```sh
npm run build
```

إعداد Cloudflare Pages:

- Build command: `npm run build`
- Build output directory: `dist`
- Node.js: `22`

لا تنشر جذر المستودع؛ `dist` هو المجلد العام. يحتوي الجذر كود الدوال والاختبارات والتوثيق.

## حدود صريحة

- التسجيل العام للضيف معطل مؤقتًا في الواجهة؛ لا يُعاد فتحه قبل اختيار مزود تحقق واختباره.
- خيار الفيديو طلب عمل تصميمي يسلمه الفريق؛ المنصة لا تولد فيديو آليًا.
- بدء الاسترداد يتم من لوحة Moyasar حاليًا؛ النظام يزامن الحالة ولا يبدأ العملية.
- واجهة الطلبات تعرض أحدث 100 طلب؛ تقرير الضيوف الكامل مرقّم حتى 10,000 ضيف.
- WhatsApp والدفع الحقيقي يعتمدان على موافقات وحسابات خارجية لا يمكن تضمينها داخل ZIP.
- هذا المستودع ليس شهادة خلو من الثغرات؛ الاختبار على مشروع تجريبي والمراجعة القانونية شرطان قبل البيع الفعلي.
