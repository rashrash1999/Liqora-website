# medad Al tahaya — منصة الدعوات الإلكترونية

نسخة إطلاق مرشحة لمنصة **مداد التحايا**: باقات وتسعير، دخول موثّق بالجوال، طلب مناسبة، دفع مستضاف عبر Moyasar، تصميم واعتماد، تسجيل مفتوح أو قائمة خاصة، RSVP، WhatsApp وتذكيرات مجدولة، تقارير، وبوابة استقبال.

بعد تسجيل دخول العميل بنجاح يعود إلى الصفحة الرئيسية، ومنها يفتح لوحة التحكم التي تفصل بين
الطلبات الحالية والسابقة وتتيح تحديث الاسم الشخصي. رقم الجوال يبقى للقراءة فقط لأنه معرّف
الدخول ويتطلب رمز تحقق عند تغييره.

## ما يعمل في الكود

- ثلاث باقات: البطاقة الذكية، موقع المناسبة المميز، ومداد أعمال.
- تسعير تلقائي للباقتين الفرديتين بحسب عدد أرقام الدعوات والإضافات، وعرض سعر إداري لباقة الأعمال.
- فصل **عدد أرقام الدعوات** عن **سعة الحضور** التي تشمل المرافقين.
- تسجيل مفتوح يتحقق من رقم الجوال، يمنع التكرار، يدعم حتى مرافقين بالأسماء، ويحوّل الزيادة إلى قائمة انتظار عند اختيارها.
- قائمة خاصة عبر CSV مع تصنيف عام/رجالي/نسائي وروابط شخصية موقعة.
- عرض تصميم جاهز أو صورة تصميم مخصص خاصة، ثم اعتماد النسخة من العميل قبل النشر.
- دفع Moyasar مستضاف؛ بيانات البطاقة لا تمر بالموقع أو Firestore، ولا تصبح الحالة `paid` من رابط العودة.
- إرسال دعوات وتذكيرات بقوالب WhatsApp Cloud API المعتمدة، مع سجل تسليم ومنع التكرار.
- QR منفصل عن رابط الدعوة، وتسجيل دخول ذري لا يضاعف العدادات.
- تقارير كاملة مرقمة حتى الحد التشغيلي 10,000 ضيف، تشمل الجوال والرد والمرافقين والدخول وعدم الحضور والرسائل.

## رحلة العميل والضيف

1. يدخل العميل برقم جوال سعودي موثّق ويختار الباقة وعدد الدعوات والسعة وطريقة التسجيل.
2. يضيف بيانات المناسبة والتصميم والتذكيرات. يعيد الخادم التحقق من كل حقل ويحسب السعر.
3. للباقات الفردية يصبح السعر المعتمد متاحًا مباشرة؛ باقة الأعمال تنتظر عرض الإدارة.
4. ينشئ الخادم فاتورة Moyasar مستضافة ويتحقق من نتيجتها خادميًا.
5. للقالب الجاهز توجد نسخة قابلة للاعتماد، وللتصميم المخصص يرفع الفريق الصورة النهائية ويعتمدها العميل.
6. ينشر العميل رابط التسجيل العام، أو تستورد الإدارة قائمة خاصة وتصدر الروابط الشخصية.
7. يسجل الضيف رده ومرافقيه ورسالة اختيارية. الرقم المكرر يستعيد التسجيل نفسه ولا يستهلك دعوة جديدة.
8. تظهر الإحصاءات للعميل والإدارة، وتُرسل التذكيرات المختارة، ثم تمسح بوابة الاستقبال بطاقة QR مرة واحدة.

## ما يحتاج إعداد المالك قبل التشغيل الحقيقي

الكود لا يحتوي أسرارًا، ولا يمكنه إرسال SMS أو WhatsApp أو تحصيل دفعة بمجرد فك ZIP. يلزم:

1. خطة Firebase تدعم Functions وPhone Authentication، مع App Check ونطاقات مصرح بها.
2. أسرار Moyasar وWhatsApp في Firebase Secret Manager، ومعرّف رقم WhatsApp وقالبان عربيان معتمدان.
3. نشر قواعد Firestore وStorage والفهارس والدوال المجدولة.
4. بناء `dist` ونشره على Cloudflare Pages.
5. نجاح اختبارات Firebase Emulator ثم تجربة كاملة في Sandbox قبل مفاتيح الإنتاج.
6. مراجعة قانونية لسياسة الخصوصية والشروط وسياسة الإلغاء والاسترداد.

## فصل الدفع

- واجهة الدفع: `checkout.html` و`js/checkout.js`.
- نموذج العرض الآمن: `js/payment/checkout-model.js`.
- تحقق السعر: `functions/payment/domain.js`.
- عميل Moyasar السري: `functions/payment/moyasar.js`.
- المعاملات وربط الفواتير: `functions/service.js`.
- Callable Functions وCallback: `functions/index.js`.

المبالغ أعداد صحيحة بالهللات ومن الخادم. معرف العملية يمنع إنشاء فاتورتين عند إعادة المحاولة، وتُطابق الفاتورة الرسمية مع الطلب والمبلغ والعملة قبل قبول الدفع.

## التشغيل المحلي

المتطلبات: Node.js 22 وJava 21 أو أحدث لاختبارات Firebase Emulator Suite.

```sh
npm ci
npm test
npm run test:integration
npm run serve
```

ثم افتح `http://127.0.0.1:4173`. استخدم مشروعًا تجريبيًا وأرقام اختبار Firebase فقط.

## البناء والنشر

```sh
npm run build
```

إعداد Cloudflare Pages:

- Build command: `npm run build`
- Build output directory: `dist`
- Node.js: `22`

لا تنشر جذر المستودع؛ `dist` هو المجلد العام. يحتوي الجذر كود الدوال والاختبارات والتوثيق.

## حدود صريحة

- خيار الفيديو طلب عمل تصميمي يسلمه الفريق؛ المنصة لا تولد فيديو آليًا.
- بدء الاسترداد يتم من لوحة Moyasar حاليًا؛ النظام يزامن الحالة ولا يبدأ العملية.
- واجهة الطلبات تعرض أحدث 100 طلب؛ تقرير الضيوف الكامل مرقّم حتى 10,000 ضيف.
- WhatsApp وSMS والدفع الحقيقي تعتمد على موافقات وحسابات خارجية لا يمكن تضمينها داخل ZIP.
- هذا المستودع ليس شهادة خلو من الثغرات؛ الاختبار على مشروع تجريبي والمراجعة القانونية شرطان قبل البيع الفعلي.
