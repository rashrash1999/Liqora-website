# معمارية منصة مداد التحايا

الواجهة HTML وJavaScript Modules تُبنى إلى `dist` وتُنشر على Cloudflare Pages. المصادقة والبيانات والعمليات الحساسة والجدولة في Firebase، والدفع في صفحة Moyasar المستضافة، والإرسال عبر WhatsApp Cloud API.

| المكوّن                  | المسؤولية                                        |
| ------------------------ | ------------------------------------------------ |
| Firebase Authentication  | SMS للعملاء، وبريد وكلمة مرور للإدارة والاستقبال |
| Custom Claims            | دورا `admin` و`gate` من أدوات خادمية موثوقة      |
| Cloud Firestore          | الطلبات والضيوف والردود والجداول والسجلات        |
| Callable Cloud Functions | الملكية والتسعير والدفع والنشر والرد والتقارير   |
| Scheduled Function       | إرسال التذكيرات المستحقة كل خمس دقائق            |
| App Check                | إثبات مصدر الاستدعاءات في الإنتاج                |
| Cloud Storage            | مراجع العميل والتصاميم الخاصة                    |
| Moyasar Invoice API      | صفحة دفع مستضافة وحالة فاتورة موثقة خادميًا      |
| WhatsApp Cloud API       | قوالب الدعوة والتذكير المعتمدة وسجل التسليم      |

## حالات الطلب

- `pending_payment`: السعر الفردي معتمد أو عرض الأعمال جاهز، ولم يُدفع.
- `awaiting_quote`: باقة الأعمال قبل اعتماد الإدارة للسعر.
- `paid`: أكد Moyasar الدفعة، ولم يكتمل التصميم بعد.
- `preparing`: تصميم مخصص مرفوع وينتظر اعتماد العميل.
- `ready`: الدفع والتصميم مكتملان ويمكن النشر.
- `active`: رابط عام أو روابط شخصية صالحة والتذكيرات مجدولة.
- `cancelled` / `completed`: حالات نهائية تمنع التعديل.

## رحلة الطلب

1. يتحقق العميل من جواله، ويختار الباقة وعدد أرقام الدعوات وسعة المقاعد وطريقة التسجيل.
2. `createOrder` يعيد التطبيع والتسعير ويربط الطلب بالـUID والجوال الموثق. حقول السعر أو الصلاحية القادمة من المتصفح مرفوضة.
3. الباقتان الفرديتان تحصلان على سعر آلي معتمد؛ باقة الأعمال تبقى `awaiting_quote` إلى أن تعتمد الإدارة العرض.
4. `createPaymentSession` ينشئ فاتورة Moyasar مستضافة. Callback أو مزامنة العميل يجلب النسخة الرسمية ويطابق المبلغ والعملة والربط.
5. القالب الجاهز يُعتمد تلقائيًا، أما التصميم المخصص فيُرفع بعد الدفع ويعتمد العميل النسخة الحالية بالضبط. يظهر التصميم للضيف برابط Storage مؤقت مدته 15 دقيقة.
6. في التسجيل المفتوح ينشر العميل رابطًا واحدًا؛ في الوضع الخاص تستورد الإدارة CSV وتصدر رابطًا شخصيًا لكل رقم.
7. يسجل الضيف الحضور أو الاعتذار والمرافقين والرسالة. الرقم نفسه لا ينشئ سجلًا ثانيًا. تجاوز المقاعد يُرفض أو ينتقل إلى قائمة الانتظار وفق الاختيار.
8. التذكيرات ترسل للمعلّقين والمؤكدين فقط، على صفحات من 100 ضيف وبـ10 عمليات متوازية، مع قفل وسجل يمنعان التكرار.
9. بطاقة QR مختلفة عن رابط الدعوة. تسجيل الدخول الذري يمنع العد مرتين، وإعادة فتح الرد تعكس عدادات الحضور والدخول.
10. التقارير تُجلب على صفحات 500 ضيف حتى 10,000 بدل استجابة ضخمة واحدة.

## قواعد السعة

- `invitationLimit`: عدد أرقام الجوال الفريدة المسموح تسجيلها أو استيرادها.
- `seatCapacity`: مجموع الحاضرين الأساسيين والمرافقين المقبولين.
- يمكن لكل دعوة إضافة صفر إلى مرافقين اثنين حسب إعداد المناسبة أو صف CSV.
- يصل تنبيه عند عبور 80% و90% و100% من السعة.
- عند امتلاء المقاعد: يرفض النظام تسجيل حضور جديد، أو يسجله `waitlist` إذا فعّل العميل قائمة الانتظار.
- امتلاء `invitationLimit` يمنع أرقامًا جديدة حتى لو بقيت مقاعد؛ التسجيل السابق يظل قابلًا للاستعادة.

## حدود تشغيلية معلنة

- لوحتا العميل والإدارة تستمعان لأحدث 100 طلب. يلزم ترقيم قائمة الطلبات عند نمو الحساب فوق ذلك.
- CSV حتى 2MB و10,000 سطر، ويُرسل للخادم على دفعات 200. إعادة الملف لا تكرر الأرقام المحفوظة.
- إنشاء الروابط حتى 100 ضيف في كل استدعاء، وإرسال WhatsApp حتى 25 في استدعاء من الواجهة.
- التقرير الكامل مرقّم 500 في الصفحة وبحد 10,000 ضيف.
- الملفات المرجعية ثلاثة، والتصميم صورة واحدة، وكل ملف حتى 10MB. فحص التوقيع والنوع ليس فحص برمجيات ضارة شاملًا.
- بوابة الاستقبال تعمل من أربع ساعات قبل المناسبة إلى ست ساعات بعدها.
- خيار الفيديو تسليم تشغيلي من فريق التصميم، وليس مولد فيديو داخل المنصة.
- بدء استرداد Moyasar ليس في اللوحة؛ مزامنة حالة الاسترداد موجودة.

## خصائص الأمان

رموز التسجيل العام والروابط الشخصية وبطاقات الدخول مشتقة بـHMAC من سر خادمي، ولا تخزن خامًا في Firestore. روابط الضيف توضع في fragment فلا تصل تلقائيًا إلى الخادم المستضيف. قواعد Firestore تمنع الكتابات المباشرة، وStorage لا يسمح بملف دون حجز يطابق المالك والحجم والنوع. تغيير مفتاح التوقيع أثناء وجود مناسبات نشطة يحتاج خطة انتقال لأنه يبطل الروابط والبطاقات القديمة.
