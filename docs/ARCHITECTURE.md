# المعمارية بعد الإصلاح

الواجهة صفحات HTML وJavaScript Modules، ويمكن إبقاء استضافتها على GitHub Pages. توجد البيانات والعمليات الحساسة في Firebase، ولا يلزم نقل الاستضافة لربط Firestore.

| المكون                   | المسؤولية                                                          |
| ------------------------ | ------------------------------------------------------------------ |
| Firebase Authentication  | SMS حقيقي للعميل، وبريد وكلمة مرور للإدارة والاستقبال              |
| Custom Claims            | صلاحيات `admin` و`gate` تصدر من أداة موثوقة، لا من الواجهة         |
| Cloud Firestore          | الطلبات والضيوف والردود والحالات وسجل العمليات                     |
| Callable Cloud Functions | ملكية الطلب، السعر، الاستيراد، إصدار الروابط، الرد، تسجيل الدخول   |
| App Check                | رفض استدعاءات الدوال التي لا تحمل إثبات التطبيق في الإنتاج         |
| Cloud Storage            | ملفات مرجعية وتصاميم خاصة، مع حجز رفع مسبق والتحقق من النوع والحجم |

## البيانات

| المسار                                     | من يقرأه؟                                                | من يكتبه؟             |
| ------------------------------------------ | -------------------------------------------------------- | --------------------- |
| `orders/{orderId}`                         | صاحب الطلب والإدارة                                      | الدوال فقط            |
| `orders/{orderId}/guests/{guestId}`        | صاحب الطلب والإدارة؛ الجوال مخفي                         | الدوال فقط            |
| `orders/{orderId}/guestContacts/{guestId}` | الدوال فقط؛ تستخرج الأرقام للإدارة عند إصدار ملف الروابط | الدوال فقط            |
| `inviteTokens/{hash}`                      | الدوال فقط                                               | الدوال فقط            |
| `ticketTokens/{hash}`                      | الدوال فقط                                               | الدوال فقط            |
| `gateAssignments/{uid}/orders/{id}`        | الدوال وأداة المشغّل الموثوق                             | أداة المشغّل الموثوق  |
| `uploads/{uploadId}`                       | الدوال وقواعد Storage                                    | الدوال فقط            |
| `auditLogs/{id}`                           | أدوات الإدارة الخادمية                                   | الدوال وأداة التعيين  |
| `rateLimits/{id}`                          | الدوال فقط                                               | الدوال فقط؛ TTL للحذف |

تُخزّن أوقات العمليات بالملي ثانية من الخادم. تاريخ المناسبة يُفسّر دائمًا بتوقيت الرياض. `expiresAt` في عدادات المعدل هو Timestamp لتطبيق TTL.

## رحلة الطلب

1. يسجل العميل دخوله برقم الجوال، ويختار الباقة ويكمل جميع الحقول والشروط.
2. تعيد الدالة حساب المبلغ المبدئي وتربط الطلب بـUID ورقم الجوال الموثق.
3. يدخل الطلب `pending_payment` أو `awaiting_quote` إذا احتاج عرض سعر للإضافات أو الباقة المخصصة.
4. **الانتقال إلى الدفع الموثق متوقف إلى حين تنفيذ مزود الدفع وWebhook والتحقق من المبلغ والعملة.** لا يوجد بديل تلقائي يغيّر `paymentStatus` من العميل.
5. بعد تأكيد الدفع الخادمي، ترفع الإدارة التصميم وقائمة الضيوف؛ يعتمد العميل نسخة محددة من التصميم.
6. تصدر الإدارة روابط فردية وتنزّل ملفًا للمشاركة اليدوية. التجديد يلغي الروابط السابقة للضيوف الذين لم يردوا.
7. يسجل الضيف ردًا واحدًا؛ ينتج رمز بطاقة مختلف عن رمز رابط الدعوة عند الموافقة.
8. يستقبل الموظف المعيّن للمناسبة الضيف. تسجيل الدخول المتزامن لا يزيد العداد مرتين.

تسمية `active` تعني أن روابط الدعوات أصبحت صالحة، ولا تعني إرسال رسالة. عدد الضيوف في الباقة يعني عدد الدعوات/أرقام المدعوين؛ المرافقون يُحسبون لكل دعوة ويظهرون منفصلين.

## حدود مقصودة

- آخر 100 طلب في قوائم العميل والإدارة؛ البحث والتصفية داخل هذه المجموعة فقط ومذكور ذلك في الصفحة. أضف pagination قبل تجاوز هذا الحجم تشغيليًا.
- CSV حتى 2MB و10000 سطر، وبحد أقصى 200 ضيف في معاملة واحدة. قد ينجح جزء من الملف قبل فشل دفعة لاحقة، ويُذكر العدد المحفوظ. إعادة الملف لا تكرر الأرقام الموجودة.
- إصدار الروابط بدفعات حتى 100 ضيف؛ عند فشل دفعة لاحقة يُنزّل ملف بالروابط التي أُنشئت بنجاح.
- الحد المرجعي ثلاثة ملفات حتى 10MB؛ لا تُعدّ معاينة توقيع الملف فحصًا شاملًا للبرامج الضارة.
- عرض QR يتم عبر صورة يولدها الخادم؛ قراءة الكاميرا تعتمد على دعم `BarcodeDetector`، مع بديل الإدخال اليدوي.
- البوابة من أربع ساعات قبل المناسبة إلى ست ساعات بعدها. تعديل هذه السياسة لاحقًا يتطلب تغييرًا خادميًا واختبارًا.
- لا يوجد إرسال WhatsApp أو عامل تذكيرات أو استرداد مدفوعات أو معالجة تلقائية لانتهاء المناسبات في هذا الإصدار.
- اعتماد التصميم الحالي لا يبدّل آليًا القالب المرئي للدعوة: تُحفظ الصورة لاعتمادها، بينما تعرض صفحة الدعوة القالب العام ببيانات المناسبة. تخصيص القوالب والفيديو والصيغ المدفوعة يحتاج تنفيذًا منفصلًا قبل بيعه كميزة عاملة.

لا تُخزّن رموز الدعوات الخام في Firestore. رمز QR مشتق بـHMAC من مفتاح خادمي ورابط الضيف، ويُخزّن تجزئته فقط. تغيير مفتاح التوقيع يتطلب خطة انتقال للبطاقات القائمة؛ لا تغيّره عشوائيًا أثناء مناسبة نشطة.
