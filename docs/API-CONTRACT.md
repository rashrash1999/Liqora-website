# عقد API المقترح — الإصدار الأول

المسار الأساسي: `/api/v1`. جميع عمليات الإدارة والعميل تتطلب جلسة آمنة وصلاحية مناسبة. الأمثلة أدناه تصف العقد وليست مطبقة في الواجهة الساكنة.

## المصادقة

| الطريقة | المسار | الغرض |
|---|---|---|
| `POST` | `/auth/admin/login` | التحقق من بريد الإدارة وكلمة المرور وإنشاء جلسة آمنة |
| `POST` | `/auth/customer/otp/request` | إرسال رمز إلى الجوال المرتبط بطلب |
| `POST` | `/auth/customer/otp/verify` | التحقق من الرمز وإنشاء جلسة العميل |
| `POST` | `/auth/logout` | إلغاء الجلسة الحالية |
| `POST` | `/auth/refresh` | تدوير جلسة قصيرة العمر عند الحاجة |

استخدم Cookies من نوع `HttpOnly` و`Secure` و`SameSite=Lax`، وحدودًا لمحاولات الدخول وطلبات OTP، ولا ترسل سببًا يكشف إن كان رقم جوال معينًا مسجلًا.

## الطلبات والمناسبات

| الطريقة | المسار | الغرض |
|---|---|---|
| `POST` | `/orders` | إنشاء مسودة طلب |
| `GET` | `/orders/:id` | قراءة الطلب بحسب الصلاحية |
| `PATCH` | `/orders/:id` | تحديث البيانات المسموحة |
| `POST` | `/orders/:id/submit` | تثبيت الطلب وبدء الدفع |
| `POST` | `/payments/webhook` | استقبال حالة دفع موقّعة |
| `POST` | `/orders/:id/approve-design` | اعتماد التصميم |

## الضيوف والإرسال

| الطريقة | المسار | الغرض |
|---|---|---|
| `POST` | `/events/:id/guests/import` | رفع CSV، التحقق وإظهار معاينة |
| `POST` | `/events/:id/guests/import/commit` | اعتماد الاستيراد بعد المراجعة |
| `GET` | `/events/:id/guests` | البحث والتصفية والتصدير |
| `POST` | `/events/:id/invitations/send` | إنشاء مهمة إرسال idempotent |
| `POST` | `/events/:id/reminders/schedule` | جدولة 24/48/72 ساعة للمؤكدين |
| `GET` | `/events/:id/delivery-report` | حالات الإرسال والتسليم والفشل |

## RSVP والدخول

| الطريقة | المسار | الغرض |
|---|---|---|
| `GET` | `/public/rsvp/:token` | قراءة بيانات العرض الدنيا إن كان الرمز صالحًا |
| `POST` | `/public/rsvp/:token` | حفظ رد واحد واستهلاك الرمز ذريًا |
| `POST` | `/gate/verify` | التحقق من رمز QR دون تسجيل دخول |
| `POST` | `/gate/check-in` | تسجيل دخول واحد مع idempotency |

مثال رد RSVP ناجح:

```json
{
  "status": "accepted",
  "guest": { "displayName": "نورة السبيعي", "companions": 2 },
  "ticket": { "qrPayload": "opaque-signed-token", "expiresAt": "2026-10-12T23:59:00+03:00" }
}
```

## قواعد موحّدة

- لا تعِد أرقام الجوال كاملة في استجابات القوائم؛ استخدم masking.
- كل أوامر الدفع والإرسال والدخول تقبل `Idempotency-Key`.
- أخطاء التحقق تستخدم `422`، التعارض مثل RSVP مستخدم يستخدم `409`، وانتهاء الرمز يستخدم `410`.
- تحقق من Webhooks بالتوقيع وسجّل معرّف الحدث لمنع إعادة المعالجة.
