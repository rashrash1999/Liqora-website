## نطاق النتيجة

المراجعة لملفات ZIP المرفقة، وليست اختبار اختراق للخدمة المنشورة أو مراجعة إعدادات حساب Firebase. الصور تُظهر المستودع نفسه `rashrash1999/Liqora-website` عبر واجهتي GitHub وVS Code Web؛ الرابط والبيئة مختلفان رغم وحدة مصدر المشروع. لا تعني الصورة أن Firebase متصل بالفعل. النسخة المعدلة هنا لم تُرفع إلى GitHub ولم تُنشر إلى Firebase.

## الاختبارات وحدود الثقة

- اجتازت 26 حالة اختبار محلية: قواعد المجال والدفع، مسار الخدمة مع قاعدة معاملات داخل الذاكرة، واختبارات DOM للنماذج والمتحكمات وحالة الإعداد الناقص.
- اجتاز التحقق من المراجع المحلية في 14 صفحة HTML وبناء حزمة Firebase.
- تختبر الخدمة رفض صلاحية خاطئة وطلب مكرر وسعر مزوّر وحدود الضيوف وتدوير الروابط والتزامن في الرد وتسجيل الدخول.
- اختبارات محاكيات Firebase مكتوبة، لكن لم تُنفذ هنا لأن Java 21 غير متاح في بيئة الفحص الحالية. لذلك لم يُثبت تجريبيًا قبول قواعد Firestore/Storage أو فعاليتها على المحاكي.
- اختبارات التكامل تستدعي الخدمة ضد Firestore المحاكى وتختبر القواعد؛ لا تغطي شبكة Callable وApp Check وSMS الحقيقية. يلزم اختبارها في مشروع تجريبي.
- أُضيف workflow إلى GitHub لتشغيل الاختبارات مع Java 21؛ لم يُشغّل على GitHub في هذه المهمة.
- لم ينجح تشغيل متصفح فعلي في البيئة؛ اختبارات DOM ليست بديلًا عن اختبار الهاتف والكاميرا وreCAPTCHA والمتصفحات.

## المتبقي قبل التشغيل التجاري

1. إدخال إعداد تطبيق Firebase وApp Check، وتفعيل الخدمات ونشر الدوال والقواعد والفهارس بعد نجاح المحاكي.
2. تنفيذ مزود دفع موثوق وWebhook يتحقق من التوقيع والمبلغ والعملة ومعرّف الطلب والتكرار. لا تغيّر paid يدويًا كبديل تجاري.
3. اختيار مزود رسائل وتنفيذ الإرسال والتذكيرات والمحاولات وسجل التسليم؛ الإصدار الحالي يتيح ملف روابط للمشاركة اليدوية فقط.
4. تخصيص القالب المرئي حسب التصميم المعتمد لم يُنفذ؛ لا تُبع ميزات فيديو أو قوالب مخصصة على أنها تعمل آليًا الآن.
5. اختبار شامل بعميل وإدارة وموظف استقبال وضيف، ومع حسابين مختلفين للتحقق من العزل، ثم اختبار التحميل والحصص والتكلفة.
6. اعتماد سياسة الاحتفاظ والحذف والنسخ الاحتياطي ومراقبة الأخطاء، وإضافة ترقيم صفحات عند تجاوز آخر 100 طلب.
7. روابط الدعوة والتذاكر صلاحيات حاملها: من يحصل على الرابط يمكنه استعماله. لا تضمن المنظومة وحدها هوية الشخص عند البوابة؛ يُراجع الاسم وفق إجراء التشغيل.
8. فحص توقيع ملف لا يعادل فحصًا مضادًا للبرمجيات الضارة. App Check وحدود المعدل طبقات تخفيف وليست ضمانًا لمنع جميع الإساءة.

النسخة أصلحت المشكلات التي غطتها المراجعة، لكنها ليست شهادة خلو من الثغرات ولا نسخة إنتاج مكتملة قبل إغلاق البنود أعلاه.

## اعتماديات التشغيل

كشف فحص npm تنبيه UUID غير مباشر عبر gaxios 6.7.1. ثُبّت override محدد إلى uuid 11.1.1 في المشروع والخلفية. تستخدم gaxios الدالة v4 عبر CommonJS؛ اجتاز استيرادها وتوليد قيمة صحيحة فحص التوافق المحلي. راجع هذا override عند تحديث Google Cloud Storage. لا يغطي فحص npm المكتبات التي لم تُسجل لها تنبيهات بعد.

## سحب الصلاحيات

تقرأ الدوال بيانات المستخدم الحالية وتفحص إلغاء الجلسة. أما قواعد قراءة Firestore وStorage فتستخدم مطالبات رمز الدخول؛ قد تبقى صلاحية القراءة في رمز سابق حتى انتهاء عمره. للحالات الطارئة التي تتطلب سحب قراءة فوريًا، أضف سجل صلاحيات/إبطال تتحقق منه القواعد واختبره قبل التشغيل.

بعد التحديث: أعاد `npm audit --omit=dev` صفرًا من التنبيهات المسجلة لاعتماديات الإنتاج، ونجحت الاختبارات المحلية الـ26 مرة أخرى. يعرض الفحص الكامل خمسة تنبيهات متوسطة في اعتماديات تطوير غير مباشرة ضمن `firebase-tools`؛ لا تدخل هذه الحزم في ملفات الموقع المنشورة أو دوال الإنتاج، ولا يوفر الإصدار الحالي من الأداة إصلاحًا آمنًا لها دون خفض قسري وكاسر للإصدار. يجب إعادة فحصها عند تحديث Firebase CLI.
